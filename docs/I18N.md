# UI Localization (i18n)

Quar Animator ships in English by default. Users can switch the whole editor
interface to Simplified Chinese, and can load their own translation catalog,
from **Edit › Preferences** (`Ctrl/Cmd+,`). The language choice and any imported
catalog are remembered in `localStorage` and restored on the next visit.

This document explains how the localization layer works and how to maintain it.

## Design

The editor is a large React codebase (150+ components) whose UI strings were
hard-coded in JSX, and thousands of tests assert against the English labels.
Localization is therefore built in two complementary layers:

1. **Components read the catalog.** Visible English strings were replaced with
   `t('English text')`. `t()` resolves the source text to a namespaced key and
   returns the current locale's translation. English is the identity case, so
   all existing English assertions keep passing.
2. **A DOM engine covers the rest.** Some strings live in module-level
   constants (for example the keyboard-shortcut list) that are evaluated once
   at load time and cannot be made reactive with `t()` alone. A
   `MutationObserver` watches the rendered DOM and translates any visible text
   node or tooltip that matches the catalog. Every translated node remembers
   its English source, so language switches and catalog re-imports refresh it
   in place, and the engine's own writes don't loop.

Only exact catalog matches are replaced. Dynamic values — project names,
numbers, font names, user content — are never in the catalog and are untouched.

## Catalog format and key naming

Catalog keys are dot-namespaced in the form **`domain.control.purpose`**:

```json
{
  "menu.file.save-as": "另存为...",
  "layout.timeline.timeline": "时间轴",
  "ui.preferences.language": "语言"
}
```

- **domain** — broad area (`menu`, `layout`, `ui`, `canvas`, `timeline`, `page`, …)
- **control** — the component or menu the string belongs to (`file`, `menu-bar`,
  `timeline`, `preferences`, …)
- **purpose** — a lower-kebab-case slug of the English text (`save-as`,
  `new-project`, `language`)

Every catalog shares the same key set, and each keeps the `{placeholder}` of its
English source. The test suite asserts both for every locale, so a key added to
one catalog fails the suite until the others have it too.

Callers do **not** hard-code these keys. Components pass the English source to
`t('Save As...')`; `keys.json` maps that source to its namespaced key. When you
add a new UI string:

1. Add the English source to `keys.json` with a fresh namespaced key.
2. Add that same key to **every** catalog — `en.json` (→ English text),
   `zh-CN.json` (→ Simplified Chinese), `zh-TW.json` (→ Traditional Chinese) and
   `ja.json` (→ Japanese).
3. Use `t('English source')` in the component, or leave the plain English text
   in JSX and let the DOM engine translate it.
4. Run the i18n tests; the key-set and non-empty checks catch typos.

### Sentences whose word order changes

A sentence that mixes text with runtime values (`2 slides, one after another: …`)
cannot be translated fragment by fragment: Chinese puts the measure word after
the number and often reorders the clause. Such sentences use `tf()` instead,
which looks the key up directly and interpolates `{name}` placeholders:

```tsx
const locale = useLocale();           // subscribe, so a language switch re-renders
…
{tf('sequence.window.after-step', { n: index + 1 }, locale)}
```

```json
"sequence.window.after-step": "After #{n}"     // en
"sequence.window.after-step": "#{n} 之后"       // zh-CN
```

Because the rendered text no longer matches an English source, the DOM engine
cannot trace it back; passing `useLocale()` is what keeps it switching
correctly. Prefer `t()` for ordinary labels and `tf()` only where word order
differs.

### Missing entries fall back to English

If the active catalog has no value for a key, the English source string is
shown. This also applies to **partial imports**: a user can import a catalog
containing only a few keys and the rest of the interface stays English, rather
than going blank or showing raw keys.

## Locale state

`store.ts` keeps the locale at module scope via `useSyncExternalStore` (the same
pattern as `useUiTheme`). It reads/writes `localStorage` key
`quar-animator-locale` (default `en`) and sets `document.documentElement.lang`
plus the page's meta description. Components use `useLocale()` and change it
with `setLocale()` / `toggleLocale()`.

Shipped locales are `en`, `zh-CN`, `zh-TW` and `ja`; `LOCALES` in `store.ts` is
the single list the persistence validator, the catalog loader and
`toggleLocale()` all read. To add one:

1. Copy `en.json` to `<locale>.json`, translate the values and keep the keys.
2. Add the code to the `Locale` union and to `LOCALES`.
3. Add a `{ id, label }` entry to `LANGUAGES` in `PreferencesDialog.tsx` — the
   label stays in its own language (`日本語`, not `Japanese`), as language
   pickers conventionally do.

The i18n tests fail until the new catalog has every key with the same
`{placeholder}`s, so a partial translation can't land silently.

## Preferences and custom catalogs

`PreferencesDialog` follows the editor's imperative dialog + host pattern
(like `ExportDialog`): `showPreferences()` opens it and `<PreferencesDialogHost/>`
is mounted once in `Editor`. It uses a blurred backdrop, closes on outside click
or Escape, and plays the same enter/exit animations as other dialogs.

Its single **General** tab provides:

- **Language** — a listbox for English / 中文（简体）/ 中文（繁體）/ 日本語.
- **Translation dictionary** — export the active catalog as a JSON template,
  import a custom JSON catalog, or reset to the built-in one. Imported catalogs
  are validated (JSON object, string values only), persisted in `localStorage`
  under `quar-animator-i18n-catalogs`, and applied immediately across the UI;
  missing keys fall back to English.

`applyDictionary(locale, json)`, `exportDictionary(locale)` and
`restoreDictionary(locale)` in `./i18n` are the programmatic equivalents.

## Engine lifecycle

`installI18n()` runs once in `main.tsx` before React mounts. It starts the
observer, subscribes to locale/catalog changes, and performs an initial pass.
Installing twice is a no-op; `uninstallI18n()` exists for tests. The engine
observes `title`, `aria-label`, `placeholder` and `alt`. Text in `<script>`,
`<style>`, `<noscript>`, `data-i18n-skip` subtrees or `contenteditable`
regions is never translated.

## Tests

```bash
# Repository root, after pnpm install
pnpm --filter @quar/web exec vitest run src/i18n/index.test.ts \
  src/components/common/PreferencesDialog.test.tsx
```

Coverage: catalog parity and namespaced-key shape across all four locales,
`{placeholder}` parity, source→key resolution; English default, Chinese
translation, unknown strings, whitespace; partial
import with English fallback; invalid JSON/format rejection; template export;
DOM text/attribute translation, idempotency, `data-i18n-skip`, `<html lang>`;
and the Preferences dialog (open, tabs, backdrop/Escape close, language change,
import success/failure).

## Scope and limitations

- **Every user-visible string is covered** — menus, panels, tooltips, dialogs,
  warnings and empty states. Each catalog holds 680 entries and the components
  make ~700 `t()` calls; a scan of the rendered JSX finds no remaining English
  copy outside the exceptions below.
- **Deliberately untranslated:** single-letter field abbreviations (`BL`, `TR`,
  `Op`, `Sz`), format names (`PNG 1x`, `SVG`, `MP4`, `WebM`), unit tokens
  (`px`, `s`, `FPS`, `bone`, `points`), key names (`Esc`, `Ctrl+,`), the
  `Quar Animator` brand label, and the language names in the Preferences select.
  These are identifiers rather than prose; translating them would make the UI
  harder to read.
- The bundled **User Guide** (`docs/help/*.md`) and the repository's own
  documentation stay in English.
- Translation is exact-match only. User-authored content, project names, font
  names and numbers are never in the catalog, so they are never translated.
