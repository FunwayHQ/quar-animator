# UI Localization (i18n)

Quar Animator ships in English by default. Users can switch the entire editor
interface to Simplified Chinese from **View › 中文 (Chinese)**. The choice is
remembered in `localStorage` and restored on the next visit.

This document explains how the localization layer works and how to maintain it.

## Why a DOM translation layer?

The editor is a large React codebase (150+ components) whose UI strings are
hard-coded in JSX — there is no `t()` function or message catalog in the
components, and thousands of tests assert against the English labels. Rather
than rewrite every component (a risky, test-breaking change), localization is
applied at runtime to the **rendered DOM**:

- A `MutationObserver` watches the document for new or updated text nodes and
  tooltips.
- Each visible string is looked up as an exact key in the active locale's JSON
  dictionary; matching strings are replaced in place.
- Every translated node remembers its English source, so the mapping is
  idempotent (the engine's own DOM writes don't re-trigger translation) and
  switching back to English restores the original instantly.
- React re-renders write English strings into the DOM again; the observer
  translates them once more, so translations stay correct as the UI updates.

Only exact dictionary matches are replaced. Dynamic values — project names,
numbers, font names, user content — are never in the dictionary and are left
untouched.

## Catalog format

Both JSON files are flat maps keyed by the **exact English UI string**:

```json
{
  "New Project": "新建项目",
  "Timeline": "时间轴"
}
```

`en.json` is an identity map (`"Save": "Save"`); it exists so that both locales
always share the same keys and so `translateText` has a uniform code path.
`zh-CN.json` holds the translations.

### Rules for keys

- Use the string exactly as it appears in the UI, including capitalization,
  ellipses (`...`), and the typographic characters the editor uses (e.g. the
  `›` in `File › Import Sound`). Keys are matched **exactly**.
- Do not add entries for dynamic/user data — they will never match.
- Keep `en.json` and `zh-CN.json` keyed identically. The test suite asserts
  both catalogs have the same key set and that every Chinese value is non-empty.

### Adding or updating a translation

1. Add the English key to **both** `locales/en.json` and `locales/zh-CN.json`.
2. Run the i18n tests (see below); the key-set and non-empty checks will catch
   typos.
3. If a translated string appears with unexpected whitespace, the engine also
   tries the trimmed value and preserves the surrounding whitespace.

## Locale state

`store.ts` holds the current locale at module scope and exposes it via
`useSyncExternalStore` (the same pattern used by `useUiTheme`). It:

- reads the saved value from `localStorage` key `quar-animator-locale`
  (defaults to `en`);
- writes the value back on change;
- sets `document.documentElement.lang` and the `<meta name="description">`
  content to match the active locale.

React components read the locale with `useLocale()` and change it with
`setLocale(locale)` / `toggleLocale()`, both exported from `./i18n`.

## Engine lifecycle

`installI18n()` is called once in `main.tsx` before React mounts. It starts the
observer, subscribes to locale changes, and performs an initial translation
pass. Installing again is a no-op. `uninstallI18n()` exists for tests.

The engine observes these attributes because they carry visible text:
`title`, `aria-label`, `placeholder`, `alt`. Text inside `<script>`,
`<style>`, `<noscript>`, any element with `data-i18n-skip`, or a
`contenteditable="true"` region is never translated. Use `data-i18n-skip` when
a subtree must remain in English (for example, a code sample in a dialog).

## Switching the language in the UI

The toggle lives in the **View** menu next to **Light Appearance**, rendered as
a `MenuItem` with a checkbox (checked when Chinese is active). Clicking it calls
`setLocale` with the other locale. Because every translated node remembers its
source string, switching languages rewrites the DOM in place without a page
reload.

## Tests

```bash
# From the repository root (dependencies installed with pnpm install)
pnpm --filter @quar/web exec vitest run src/i18n/index.test.ts
```

Coverage includes: catalog parity and non-empty values; exact and whitespace-
preserving translation; text-node, tooltip and `aria-label` translation;
idempotency (no loop on the engine's own writes); `data-i18n-skip`; and the
`<html lang>` attribute.

## Scope and limitations

- This localizes the editor chrome (menus, panels, tooltips, dialogs) via the
  runtime dictionary. The bundled **User Guide** (`docs/help/*.md`) and other
  project documentation are intentionally left in English.
- Translation is exact-match only; composite strings built at runtime from
  several pieces may not match a single key and remain English. Prefer adding
  a key for the full rendered string when this matters.
- The engine translates mixed into Chinese all UI strings present in the
  catalog; it does not translate user-authored content or file formats.
